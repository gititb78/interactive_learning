בעיית הסוכן הנוסע

תארו לעצמכם סוכן שצריך לבקר במספר נקודות בעיר, בדיוק פעם אחת בכל נקודה, ולחזור להתחלה במסלול הקצר ביותר.

כדי למצוא את המסלול המיטבי, המחשב יצטרך לבדוק את כל האפשרויות הקיימות. ככל שנוסיף נקודות למפה, כמות המסלולים האפשריים הולכת וגדלה בקצב מסחרר.

התפוצצות קומבינטורית: זמני חישוב

הנה טבלה המראה כמה זמן ייקח למחשב (המבצע מיליארד פעולות בשנייה) לחשב את כל המסלולים בהתאם לכמות האטרקציות:

המסקנה: לא מספיק לכתוב קוד שעובד. אנו חייבים להעריך כמה זמן ייקח לו לרוץ.

פונקציית זמן ריצה (ספירת פקודות)

אפשר לספור במדויק כמה פעולות המחשב מבצע כתלות בגודל הקלט (n):

public static int Sum(int[] arr) { int sum = 0; /* 1 (השמה) */ int n = arr.Length; /* 1 (השמה) */ for (int i = 0; i < n; i++) /* 1 + 2n + 1 */ sum += arr[i]; /* n (חיבור והשמה) */ return sum; /* 1 (החזרה) */ }
סך הכל פעולות שיתבצעו:
1 + 1 + (2n + 2) + n + 1 = 3n + 5
ככל שהמערך (n) גדל, הפקודות הבודדות מחוץ ללולאה (ה-+5) הופכות לזניחות, והלולאה עצמה היא זו שקובעת את קצב הגידול של זמן הריצה.

מקרה ממוצע לעומת מקרה גרוע

לפעמים זמן הריצה תלוי לא רק בגודל הקלט (n), אלא גם בתוכן שלו. נתבונן בפעולת חיפוש איבר במערך:

public static int Search(int[] arr, int k) { int n = arr.Length; for (int i = 0; i < n; i++) if (arr[i] == k) return i; return -1; }
  • המקרה הטוב: k נמצא בתא הראשון. הלולאה נעצרת מיד.
  • המקרה הממוצע: k נמצא אי שם באמצע, נבדוק כ-n/2 תאים.
  • המקרה הגרוע: k לא קיים כלל (או נמצא בסוף). ניאלץ לבדוק את כל n התאים.
💡 במדעי המחשב אנחנו מתעניינים לרוב במקרה הגרוע ביותר, כדי להבטיח למשתמש שהתוכנית לעולם לא תעבור גבול מסוים.

הערכת סדר גודל (Big O Notation)

כפי שראינו, פונקציית זמן הריצה המדויקת (למשל 3n + 5) היא מפורטת מדי. בפועל, אנו מעוניינים רק בסדר הגודל של הפונקציה כש-n שואף לאינסוף.

O( complexity )

  • האות O (נקראת Big O) מציינת "בסדר גודל של...".
  • אנו מתעלמים מקבועים וממקדמים.
  • אם ספרנו 3n + 5 פעולות, נתעלם מה-5 ומהכופל 3, ונגיד שהסיבוכיות היא פשוט (n)O.
  • אם הפונקציה הייתה 5n² + 2n + 10, החזקה הגבוהה ביותר קובעת, ולכן הסיבוכיות תהיה (O(n².

דוגמאות: זמן קבוע - O(1)

// דוגמה 1: הדפסה פשוטה של הודעה public static void PrintMessage() { Console.WriteLine("Hello World!"); } // דוגמה 2: סכום איבר ראשון ואחרון public static int SumFirstLast(int[] arr) { return arr[0] + arr[arr.Length - 1]; }
(1)O - זמן קבוע

הפעולות אינן תלויות כלל בגודל של אוסף נתונים כלשהו ואין בהן לולאות.

בדוגמה השנייה, למרות שאנו מקבלים מערך, הגישה לתאים מתבצעת ישירות דרך האינדקס שלהם. חיבור שני תאים ייקח בדיוק את אותו הזמן – בין אם המערך מכיל 5 איברים ובין אם מיליון איברים.

דוגמאות: זמן לינארי - O(n)

// דוגמה 1: סכום איברי מערך (לולאה אחת) public static int SumArray(int[] arr) { int sum = 0; for(int i = 0; i < arr.Length; i++) sum += arr[i]; return sum; } // דוגמה 2: לולאות עוקבות (מקסימום והדפסתו) public static void PrintAllMax(int[] arr) { int max = arr[0]; for(int i = 1; i < arr.Length; i++) if(arr[i] > max) max = arr[i]; for(int j = 0; j < arr.Length; j++) if(arr[j] == max) Console.WriteLine(max); }
(n)O - זמן לינארי

בדוגמה השנייה יש שתי לולאות, אבל הן מופיעות אחת אחרי השנייה ולא אחת בתוך השנייה.

כמות הפעולות הכוללת היא בערך n ועוד n (כלומר 2n). מכיוון שאנו מעריכים סדר גודל (Big O) ומתעלמים מקבועים כופלים, הסיבוכיות נשארת לינארית: (n)O.

דוגמאות: זמן ריבועי - O(n²)

// דוגמה 1: לולאה בתוך לולאה public static void PrintPairs(int[] arr) { for(int i = 0; i < arr.Length; i++) for(int j = 0; j < arr.Length; j++) Console.WriteLine(arr[i] + "," + arr[j]); } // פעולת עזר O(n) שעוברת על המערך public static int CountVal(int[] arr, int val) { int count = 0; for(int i = 0; i < arr.Length; i++) if(arr[i] == val) count++; return count; } // דוגמה 2: קריאה לפעולת עזר O(n) מתוך לולאה public static void PrintFreq(int[] arr) { for(int i = 0; i < arr.Length; i++) { int c = CountVal(arr, arr[i]); Console.WriteLine(c); } }
(O(n² - זמן ריבועי

זמן ריבועי נגרם כשיש כפילות מעברים.

בדוגמה השנייה, הלולאה המקוננת "מוסתרת" בתוך קריאה לפעולת העזר CountVal.
כיוון שפעולת העזר עוברת על כל המערך (n)O, והלולאה החיצונית קוראת לה n פעמים, סך הפעולות הכולל יהיה בקירוב n * n.

לסיכום סדרי הגודל

אנו מאפיינים אלגוריתמים לפי קצב הגידול של הזמן שלהם ביחס לקלט:

  • (1)O - קבועה: היעילה ביותר. זמן הריצה נשאר זהה תמיד (קו אופקי בגרף).
  • (n)O - לינארית: זמן הריצה גדל בקצב אחיד ביחס לקלט. אם הקלט הוכפל, הזמן יוכפל (קו ישר אלכסוני).
  • (O(n² - ריבועית: זמן הריצה גדל באופן מעריכי. יעיל לקלטים קטנים, אך קורס מהר מאוד כאשר המערך הופך לגדול (פרבולה).

מבנה התשובה הנדרש במבחן

כאשר נשאלים מהי סיבוכיות זמן הריצה, חובה לענות לפי 3 שלבים ברורים במדויק:

  1. הגדרת n: הניסוח הנדרש הוא: "n - גודל המערך" (ללא תוספות מיותרות).
  2. הסיבוכיות: ציון סדר הגודל - למשל: "סיבוכיות זמן הריצה היא (n)O".
  3. נימוק: למשל: "משום שישנה לולאה בודדת העוברת על כל איברי המערך, וכל הפעולות בתוכה מתבצעות ב-(1)O".
